## [Unreleased]
### Security

- **The audit scrubber now redacts SSNs and payment-card numbers, not only secrets** (2026-09-06). `packages/governance/audit.py::scrub()` already stripped tokens, API keys and connection-URI credentials before an argument was stored in an audit row (`AuditEvent.__post_init__`), but it let personally-identifiable values ride through. `_scrub_text` now runs a narrow PII pass after the secret pass: a US SSN (separated form only) and a Luhn-valid payment-card number are replaced with `***`. Deliberately narrow — email and phone are **not** redacted, because the audit event legitimately records an owner identity (frequently an email) and both shapes are far too common in ordinary tool arguments to redact without gutting the trail's debuggability; card candidates are Luhn-checked so a 16-digit order ref or snowflake id is not mistaken for a PAN, and a bare nine-digit run is left alone. Additive and fails-closed like the rest of `scrub`. 11 tests. Files: `packages/governance/audit.py`, `tests/test_governance_audit_pii.py`.
- **Web-reach results are tagged untrusted at the source** (2026-09-04). Follow-up to the #1409 spike (item 3, a risky module gated by rule 15 — reviewed with `risky-module-review`). Every content-bearing return from `agent/web_reach.py` (`fetch_page`, `youtube_transcript`, `search_web`, `fetch_rss`) now carries `"trust": "untrusted-external"`, so any consumer — not only the Executor prompt fence from the previous change — can tell the payload is attacker-influenceable external text to be treated as DATA, never instructions. Defence-in-depth only: the SSRF boundary (rule 14 — `unsafe_target_reason` + per-hop redirect re-validation in `_safe_get`) is untouched, and error/refusal results are left untagged (no payload). Security note — changed: added a constant trust marker to success returns; risk: a consumer that ignores the marker (mitigated — the prompt fence already treats every observation as untrusted, so this is purely additive); verified: the risky-module-review skill plus the existing SSRF tests still pass. 2 tests. Files: `agent/web_reach.py`, `tests/test_web_reach.py`.
- **`/v2/agent/coordinate`'s catch-all error handler no longer leaks raw exception text to the client** (2026-09-06). `agent/coordinate.py`'s `coordinate_v2` returned `HTTPException(status_code=500, detail=str(exc))` from its outer `except Exception`, exposing internal exception text (rule 27) — the one genuine leak among a batch of changes an automated security-fix draft (PR #1444) got mostly wrong: it also rewrote the file's line endings wholesale and, in two other files, replaced intentional `ValueError`-derived 400/404 messages (client-facing validation feedback, explicitly commented as "not a server fault") with the same generic text, which would have been a user-visible regression. This PR takes only the one correct fix — the 500 now returns a generic message while `log.exception()` (already present) keeps the real detail server-side — and leaves `backend/governance_router.py` / `backend/platform_controls_router.py` untouched. Security note — changed: one `detail=` string on an unexpected-exception path; risk: none (strictly less information disclosed, response shape unchanged); verified: `tests/test_no_exception_detail_leaks.py` (now covering `agent/coordinate.py`) plus the existing coordinate/compose test suites pass. 1 new regression test. Files: `agent/coordinate.py`, `tests/test_no_exception_detail_leaks.py`.

### Added

- **Senior-Engineer-Grade Refactoring & Improvement Review Framework** (2026-09-07). Added `docs/architecture/refactoring-review-framework.md` containing a review framework with exact detection signatures, PR evaluation rubric, critical bug fixes, and an architectural refactoring roadmap for Autonomous AI Agency. Files: `docs/architecture/refactoring-review-framework.md`.
- **A connector catalogue (`/api/connectors`) with a first webhook connector — the first step toward a Zapier/Make-style integration library** (2026-09-05). The agency competes with n8n/Make/Zapier on orchestration but had no connector abstraction (`packages/integrations/` held only MCP + Render). Adds `packages/integrations/connector_registry.py` — a declarative `ConnectorSpec` catalogue mirroring `mcp_registry.MCPServerSpec` — plus one real, credential-free connector: an **outbound webhook** action that POSTs a JSON event to a public URL. The target clears `unsafe_target_reason` (rule 14) before the first request and redirects are never followed, so it cannot be turned into an SSRF/exfiltration primitive; payload and URL are never logged (rule 6). Surfaced admin-only via `backend/connectors_api.py` (`GET /api/connectors/`, `POST /api/connectors/webhook/send`), mounted guarded in `backend/server.py`. More connectors (Slack, Google Sheets) follow as their own specs in later PRs. 9 new tests (catalogue, SSRF rejection, redirect-not-followed, success path, 401/403/200 auth). Files: `packages/integrations/connector_registry.py`, `backend/connectors_api.py`, `backend/server.py`, `docs/api-surfaces.md`, `tests/test_connector_registry.py`.
- **A Workflows tab surfaces the CRISPY workflow engine in the dashboard** (2026-09-05). The engine's `/api/workflow` API (mounted admin-gated in the sibling PR) had no UI. New `WorkflowScreen` under the Work hub lists runs with their status, starts a run (`request` + optional `title`), shows each run's phase timeline, and — when a run is at the hard `awaiting_approval` gate — exposes Approve / Reject / Cancel so an admin lifts or fails the gate from the browser. Talks to the engine through six new `frontend/src/api.js` helpers on the shared axios instance (`/api/workflow/*`, so the Cloudflare worker proxies it). Requires the `/api/workflow` mount to be deployed to function. 2 new render tests (approve lifts the gate with the approver identity; start posts `{request, title}`). Files: `frontend/src/api.js`, `frontend/src/v5/screens/WorkflowScreen.jsx`, `frontend/src/v5/screens/WorkHub.jsx`, `frontend/src/__tests__/workflowScreen.test.jsx`.
- **The CRISPY workflow engine's API is now mounted and admin-gated — it was fully built but unreachable** (2026-09-05). `workflow/api.py` defined `workflow_router` (13 endpoints: `/workflow/build`; `/workflow/{run_id}` and its `approve`/`reject`/`resume`/`cancel`; and `slices`/`artifacts`/`checks`/`verify`/`events`/`agents`) plus the hard `awaiting_approval` gate, but the router was never `include_router`'d in `backend/server.py` or `proxy.py` and declared no auth — so the whole engine (n8n's actual differentiator, already backed by 47 passing tests) was dead from the outside. It is now mounted at `/api/workflow` behind a router-level admin dependency (rules 8 & 10: the engine can write code, so every endpoint requires an authenticated admin), guarded so a bad import never blocks startup. The drifted module docstring — which claimed a `proxy.py` mount and `verify_api_key` auth, neither true — is corrected to match. Documented in `docs/api-surfaces.md`. 4 new tests (401 anonymous, 403 non-admin, 200 admin, route-is-mounted-not-404). Files: `backend/server.py`, `workflow/api.py`, `docs/api-surfaces.md`, `tests/test_workflow_api_mount.py`.
- **The provider catalogue probe now runs on a schedule and files a drift issue, instead of only on manual dispatch** (2026-09-04). `.github/workflows/catalogue-probe.yml` already listed + chatted every configured provider, but was `workflow_dispatch`-only — so every dead-model incident (`z-ai/glm-5.2` 410, the Cerebras 404s/402s) was caught by a production failure or a manual run, never by the probe itself. It now also runs daily (06:00 UTC) and files **exactly one** drift-tracking issue when a routed provider is unreachable or a named model will not answer, updating that issue on repeat failures rather than duplicating it; a clean run touches no issues, and manual dispatch stays side-effect-free. The scheduled step chats the rule-4 chain defaults (nvidia/cerebras/groq/anthropic) and writes a `--json` summary consumed by the new `probe_report.py`, whose GitHub create-vs-update logic is injected and unit-tested without a network. Adds `issues: write` to the workflow (the only new permission) and a `catalogue-probe` entry to `loops/registry.yaml` (rule 35; `audit --check` green). Files: `.github/workflows/catalogue-probe.yml`, `.github/scripts/probe_catalogues.py`, `.github/scripts/probe_report.py`, `loops/registry.yaml`, `tests/test_catalogue_probe.py`, `tests/test_probe_report.py`.
- **`claude-fable-5-1` added to the model catalog** (2026-09-04). Fable 5.1 is the revised September 2026 release of Claude Fable 5 with improved instruction-following and context handling. It was already in `ADAPTIVE_THINKING_MODELS` (so temperature was correctly suppressed), but the `config/llm/models.yaml` entry and the `cost_tracker.py` pricing row were missing — making the model unroutable and its costs invisible in admin spend stats. Added with the same capabilities and pricing as Fable 5 (30.0/120.0 per 1M tokens, 200k context), at a higher priority so it is preferred when `ROUTER_ALLOW_FABLE5=1`. 27 new tests. Files: `config/llm/models.yaml`, `packages/ai/cost_tracker.py`, `tests/test_daily_automation_2026_09_04.py`.

### Fixed

- **SSRF redirect validation hardened in Web Reach** (2026-09-07). Updated `agent/web_reach.py::_safe_get` to construct target URLs for relative redirect hops using `urllib.parse.urljoin` before validating against `unsafe_target_reason()`, eliminating potential SSRF bypasses via relative location headers. Files: `agent/web_reach.py`.
- **The hourly Autonomous Agent workflow crashed on every run once the Cerebras paid tier lapsed, instead of failing over to Groq or NVIDIA** (2026-09-06). `.github/scripts/autonomous_agent.py`'s `_select_brain()` picked exactly one provider — the highest-priority one with a key present — and the single `httpx.post(...).raise_for_status()` call had no error handling at all, so a `402 Payment Required` from Cerebras (or any non-2xx from whichever provider was picked) took the whole run down even though `autonomous-agent.yml` already passes `GROQ_API_KEY` and `NVIDIA_API_KEY` as working fallbacks. `autonomous_fix.py` carried an identical duplicate of `_select_brain()` with the same single-provider selection (it happened not to crash only because its call site already sat inside a broad `except Exception: return`). Both scripts now share a new `.github/scripts/gh_brain_failover.py` (named to avoid colliding with the unrelated in-app `services/brain_failover.py`): `brain_candidates()` returns every provider with a key configured, in the documented Cerebras → Groq → Mistral → NVIDIA NIM order, and `call_brain_with_failover()` tries each in turn, skipping a candidate that raises an HTTP or transport error and only raising once all of them have failed. 10 new regression tests (candidate ordering, empty-key handling, failover on HTTP and transport errors, stops at first success, raises only when every candidate fails). Files: `.github/scripts/gh_brain_failover.py`, `.github/scripts/autonomous_agent.py`, `.github/scripts/autonomous_fix.py`, `tests/test_gh_brain_failover.py`.
